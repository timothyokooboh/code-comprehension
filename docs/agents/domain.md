# Domain docs

Use a single-context layout:
- GLOSSARY.md at the repository root.
- Architecture decision records in docs/adr/.

Before exploring the codebase, read the glossary and relevant ADRs
when present. Proceed silently when they do not exist; create them
through domain-modeling as terms and decisions are resolved.

Use the glossary's terminology consistently.
Surface conflicts with existing ADRs explicitly.
